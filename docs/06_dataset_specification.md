# 本课题数据集选型与预处理规范 v1.0

本规范把“收集一些风格文本”改造成可检验的数据设计。第一轮建议只研究一种经授权的中文个人表达风格，等流程稳定后再扩展第二种风格。

## 1. 最终要构建什么数据

训练目标不是复述作者原文，而是让模型在新主题上保持目标表达特征。因此采用三层数据：

| 数据层 | 作用 | 建议规模 | 是否进入训练 |
|---|---|---:|---|
| A. 目标风格数据 | 学习句法、语气、结构和修辞习惯 | 先构建 500 条高质量样本 | 是 |
| B. 通用指令回放 | 减少指令遵循和通用能力退化 | A 的 10%–25% | 是，单独标记 |
| C. 冻结评测集 | 评估已见/未见主题上的风格迁移 | 至少 80 条提示 | 否 |

50/100/200/500 条实验指的是 A 层训练样本数。B 层按固定比例加入，C 层始终不变。

## 2. A 层应该选择什么样的数据

### 来源要求

优先顺序：

1. 项目成员本人或明确书面授权者的原创文本；
2. 公共领域文本；
3. 许可证明确允许研究、改编与必要再分发的文本；
4. 仅允许研究使用但不可发布原文的数据，须在数据卡中标明限制且不得上传仓库。

不使用：私人聊天记录、未经同意的邮件、含大量个人信息的内容、许可证不明的网文、直接抓取的付费作品、机器生成内容冒充目标作者内容。

原始材料最好来自至少 20 个独立文档，跨越不少于 4 个主题。单一长文即使能切出 500 段，也不能视为 500 个独立样本。

### 任务组成

500 条目标风格样本建议如下：

| 类型 | 比例 | instruction/input | response |
|---|---:|---|---|
| 语义保持的风格改写 | 50% | 中性表达或事实等价文本 | 目标风格改写 |
| 提纲/要点成文 | 20% | 事实要点、结构提纲 | 目标风格完整文本 |
| 个性化问答/解释 | 20% | 与作者主题不完全重合的问题 | 符合目标表达习惯的回答 |
| 跨主题迁移 | 10% | 训练语料中少见的新主题 | 目标风格文本 |

核心是 paired data：输入与目标回答语义可对照。只有原始作者段落、没有 instruction/input 的纯续写样本最多占 10%，否则模型很难学会“按指令适配”。

### 风格覆盖

每条样本标注四个独立维度：

- `style_label`：总体风格类别；
- `style_traits`：可多选的具体属性，如短句、结论先行、设问、比喻、克制语气；
- `topic_label`：内容主题；
- `task_type`：rewrite、outline_to_text、qa、cross_topic。

风格和主题必须分开。某作者经常写科技，不等于“科技词汇”就是其风格。

## 3. B 层通用回放数据

作用是提醒模型保持基础指令遵循，而不是给模型补充新知识。优先从许可清楚的公开指令数据中人工抽取少量、高质量、多任务样本：

- [OpenAssistant/oasst1](https://huggingface.co/datasets/OpenAssistant/oasst1)：Apache-2.0，多语言对话树；需要选择中文、高评价、非敏感分支并重新审查。
- [databricks/databricks-dolly-15k](https://huggingface.co/datasets/databricks/databricks-dolly-15k)：CC BY-SA 3.0，英文人工指令数据；适合英语基线或作为任务类型参考。

不要直接随机混入海量公开指令。对中文实验，优先自行编写 50–100 条覆盖摘要、解释、分类、信息抽取、拒答和常识问答的短指令；这样许可、语言和质量最可控。

## 4. C 层冻结评测集

至少 80 条，建议结构：

- 20 条已见主题的风格改写；
- 20 条未见主题的风格改写；
- 20 条问答/解释；
- 20 条通用指令能力测试。

其中一半可有人工参考答案，另一半采用无参考 rubric 评价。评测文本必须来自未进入训练的源文档；同一事件、段落改写、相邻窗口和同一提示模板的衍生版本不得跨 split。

## 5. 预处理的严格顺序

```text
授权与来源登记
  → 原始文件只读归档
  → 文本抽取/编码统一
  → Unicode与空白归一化
  → 网页噪声和模板行清除
  → 保留文档/章节边界
  → 语义分段
  → PII与敏感信息扫描
  → 精确去重
  → 近重复聚类
  → 质量/风格/主题/任务标注
  → 按source_group冻结train/validation/test
  → 构造instruction-input-response
  → tokenizer长度审计与截断处理
  → JSONL转换、哈希和数据卡
```

先按来源划分，再生成提示词变体或增强数据；否则同一原文的不同改写容易进入不同集合。

## 6. 每一步的可执行标准

### 6.1 文本规范化

- UTF-8 保存，Unicode NFKC 归一化；
- CRLF/CR 统一为 LF；
- 合并多余空白，但保留段落边界；
- 删除导航栏、广告、版权脚注、转载声明、页码和重复标题；
- 不随意转换简繁体；如需转换，保留原文与转换版本并记录工具版本。

### 6.2 分段

- 先按章节/段落，再按完整句子组合；不从引号、列表、代码块中间切断；
- 第一轮以目标模型 tokenizer 计，response 推荐 64–512 tokens；
- prompt + response 通常控制在 1024 tokens 内，以降低显存并减少截断；
- 少于 30 个汉字的片段通常缺少稳定风格信号，除非它是完整对话或鲜明短句；
- 超长样本重新按语义拆分，不使用无提示的硬截断。

当前脚本用字符数做第一轮粗筛；选定 Qwen/Llama 具体模型后，必须用其 tokenizer 做第二轮长度审计。

### 6.3 去重

- 精确重复：规范化文本 SHA-256，一组只保留质量最高且授权最清楚者；
- 近重复：中文字符 5-gram Jaccard 或 MinHash，`similarity >= 0.85` 进入人工复核；
- 同一原文的不同 instruction 包装视为同源衍生样本，绑定同一 `source_group`；
- 先在全体数据上找重复，再做 split；不能只在各 split 内去重。

500 条规模可以用精确计算；达到万条后使用 DataTrove/Data-Juicer 的 MinHash 管线。

### 6.4 隐私、版权和安全

- 正则初筛邮箱、电话、身份证号、URL、社交账号；
- 人名、住址、单位和隐含身份信息必须人工复核；
- 脱敏替换为一致占位符，如 `<PERSON_1>`，而不是简单删除导致句子残缺；
- 每个源文档必须记录 `license`、`consent`、`redistributable`；
- 不可再分发的数据只存本地受控目录，公开仓库只发布处理代码和统计信息。

### 6.5 质量过滤

人工质量分为 1–5，训练只使用 4–5：

- 5：语义完整、风格鲜明、无噪声、指令对应准确；
- 4：可直接训练，风格明确但不极突出；
- 3：需小修或风格信号偏弱；
- 2：明显噪声、逻辑/事实问题；
- 1：错误、敏感、无授权或不可用。

同时检查复杂度与多样性：不能用大量高质量但句式完全相同的样本填满数据集。每个主风格、任务类型和主题应设最低覆盖量。

### 6.6 人工标注一致性

- 先用 30 条试标，讨论分歧后冻结 v1 标注规范；
- 20% 样本双人独立标注；
- `keep/style_label/task_type` 报告 Cohen's kappa；
- `quality` 报告加权 kappa；
- `style_traits` 报告逐标签一致率；
- 一致性不足时先改标签定义，不急于扩大数据量。

## 7. 推荐字段

```json
{
  "id": "稳定哈希ID",
  "source_id": "原文件ID",
  "source_group": "保证不跨split的来源组",
  "license": "授权或许可证",
  "consent": true,
  "redistributable": false,
  "language": "zh-CN",
  "task_type": "rewrite",
  "style_label": "argument_concise",
  "style_traits": ["short_sentence", "conclusion_first"],
  "topic_label": "technology",
  "instruction": "请用目标风格改写以下内容。",
  "input": "中性输入",
  "response": "目标风格回答",
  "quality": 5,
  "annotator_ids": ["A01", "A02"],
  "split": "train"
}
```

当前代码为兼容既有流程仍使用 `text` 表示 response；下一版可无损迁移为显式 `response` 字段。

## 8. 训练子集怎样抽取

不要独立随机抽四次。先按质量、task、style、topic 分层并固定排序，然后构建嵌套子集：

```text
train_50 ⊂ train_100 ⊂ train_200 ⊂ train_500
```

每个规模使用相同冻结验证/测试集；每个训练规模运行 3 个 seed。这样数据量曲线才可解释。

## 9. 数据验收报告必须包含

- 原始/保留/剔除样本数与剔除原因；
- 文档数、来源数、许可分布；
- task/style/topic/quality 分布；
- 字符数和 tokenizer token 数分位数；
- 精确重复和近重复簇数量；
- PII 命中及人工处理数量；
- 各 split 的来源隔离证明；
- 双人标注一致性；
- 数据版本、哈希、脚本 commit 和 tokenizer revision。

## 10. 第一轮具体执行方案

1. 选择一个有明确授权的中文个人风格，收集至少 20 个独立文档。
2. 清洗并分段得到约 1,000 个候选片段。
3. 去重、隐私和授权筛查后保留约 700 个。
4. 试标 30 条并修订标签定义。
5. 人工构造/审核 580 条：500 条训练母集 + 80 条冻结评测。
6. 另写 50–100 条通用回放数据。
7. 建立 50/100/200/500 嵌套训练集，开始 zero-shot、few-shot、LoRA、QLoRA 对比。
