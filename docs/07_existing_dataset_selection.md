# 两组现有数据集选型

本项目不再使用自行合成的参考样本。第一轮实验采用两个已经发表、可追溯的数据集：**LaMP-7** 作为个性化主基准，**GYAFC** 作为可控风格迁移对照基准。

## 1. LaMP-7：Personalized Tweet Paraphrasing

### 为什么选择

- LaMP 是专门面向语言模型个性化的公开基准，并提供七类任务。
- LaMP-7 的目标是结合用户历史文本进行个性化改写，与“低资源个性化适配”最接近。
- 官方仓库同时提供无个性化、检索增强和按用户进行 LoRA 训练的实现，便于建立可信基线。
- 官方提供 user-based 和 time-based 两套划分，可分别考察新用户泛化和对同一用户未来文本的适配。

### 官方来源

- 论文：<https://aclanthology.org/2024.acl-long.399/>
- 代码：<https://github.com/LaMP-Benchmark/LaMP>
- 数据下载：<https://lamp-benchmark.github.io/download>

### 本项目怎样使用

第一阶段只使用 **LaMP-7 user-based split**，保留官方 train/dev/test，不自行重新随机切句。每条记录中的用户历史作为 `profile`，待改写文本作为输入，官方输出作为监督目标。

从官方训练集构造 50、100、200、500 条的嵌套子集；较大的子集必须包含较小的子集。抽样和训练均按用户记录，不能把同一测试用户的目标输出泄漏进训练集。

首轮比较：

1. 基座模型，不使用用户历史；
2. 基座模型，在提示词中放入检索到的用户历史；
3. LoRA 个性化微调；
4. QLoRA 个性化微调。

主要指标采用 ROUGE/BLEU、语义相似度、风格相似度和人工盲评；同时单独报告指令遵循与内容保真，避免模型只复制用户历史。

### 限制与合规

- 数据为英文社交媒体文本，不能直接代表中文写作风格。
- 可能含用户名、链接、口语和敏感表达；训练前应做去标识化及安全过滤。
- LaMP 仓库的代码与数据整理方法采用 CC BY-NC-SA 4.0，但组成数据仍受各原始数据源许可约束。实验记录中必须保存数据版本、下载日期和来源许可。

## 2. GYAFC：Grammarly's Yahoo Answers Formality Corpus

### 为什么选择

- GYAFC 是已有论文验证的正式/非正式风格迁移语料。
- 输入与目标在内容上成对对应，适合测量“风格变化”和“语义保留”之间的平衡。
- 它不是个人作者风格数据，因此作为方法学对照，不作为个性化主结论的唯一依据。

### 官方来源

- 论文：<https://arxiv.org/abs/1803.06535>
- 官方仓库与申请说明：<https://github.com/raosudha89/GYAFC-corpus>

### 本项目怎样使用

正式化与非正式化视为两个方向，分别训练和报告结果，不把方向标签混在同一无标注任务中。保留官方验证集和测试集；只从训练集建立 50、100、200、500 条嵌套子集。

首轮比较 zero-shot、few-shot、LoRA 和 QLoRA。评价至少包含：风格分类准确率、语义相似度、BLEU/chrF、流畅度人工评分。BLEU 只作为成对参考指标，不能单独代表风格迁移质量。

### 访问与合规

完整语料不能直接从本仓库转发。官方要求研究者通过邮件说明单位和研究用途后申请。获准后，将原始文件放入 `data/raw/gyafc/`；该目录保持 Git 忽略，不提交原文。项目中只保存许可说明、校验值、处理脚本和不含原文的统计结果。

## 两组数据的分工

| 数据集 | 在课题中的角色 | 能回答的问题 | 不能单独回答的问题 |
|---|---|---|---|
| LaMP-7 | 个性化主基准 | 用户历史是否提高个性化生成；LoRA/QLoRA 的资源—效果权衡 | 中文长文本和特定中文作者风格 |
| GYAFC | 风格迁移对照 | 小样本下能否改变风格并保持内容 | 真正的用户级个性化 |

## 数据落盘约定

```text
data/
├── raw/
│   ├── lamp7/       # 官方下载，禁止手工改写
│   └── gyafc/       # 获授权后放入，不提交 Git
├── interim/         # 清洗、去标识化后的中间文件
└── processed/       # 训练使用的统一 JSONL
```

原始数据只读保存。所有清洗、抽样、切分和格式转换必须由脚本完成，并记录随机种子、输入文件 SHA-256、规则版本和输出统计。不得为了凑数量自行续写、改写或补造样本。

## 执行顺序

1. 从 LaMP 官方页下载 LaMP-7 user-based split，先完成无需申请的主实验。
2. 按 GYAFC 官方仓库说明提交学术使用申请；等待期间不从第三方镜像获取语料。
3. 对两组数据分别生成数据卡、许可记录和去标识化报告。
4. 统一转换为项目 JSONL schema，再建立 50/100/200/500 条嵌套训练子集。
