# 总方案：低资源个人定制开发者框架

更新：2026-11-02，framework_v1。以开题计划和所有者最新指示为准；不修改20/24号冻结协议，不重启完成实验。

## 1. 最终目标与本轮交付范围

帮助个人开发者在消费级显卡上，用少量本人或获授权的真实数据调整大模型，形成有实证依据、可扩展、易上手的仓库与方法指南。所有者最新明确：不必做完整MVP、桌面软件或商业产品；用可组合命令、配置模板、模块接口和启动指令集交付即可，前端作为未来可选接入方式。

现有数据设计、50–500条策略及PEFT消融继续作为LoRA选型和候选配方的证据基础。框架负责将这些研究经验转成可复用操作流程，不以新增实验数量或复杂软件功能替代研究目标。

首个示例最新确定为AI安全审查能力，重点使用指定来源的攻击案例；文本或图文模态待确认，见34号方案。仍只做一个示例。材料和案例不是当前框架开发的前置条件，不据此补造数据，也不强制为示例另做多种子大网格。

## 2. 已完成成果怎样支撑LoRA

| 证据 | 已完成内容 | 对框架的作用与边界 |
|---|---|---|
| 真实数据管线 | LaMP-7清洗、历史画像、去重与复制审计、可复现划分和资产哈希 | 提供数据规范与审计范式；当前为英文共享适配器＋历史画像，并非每个个人的独立适配器 |
| 50–500条策略 | small_sample_v1：16次训练、12个所选适配器完整评价、36项原始bootstrap | 说明训练预算、学习率和dev选择需要控制；不能将多因素同时变化称为单机制创新；另有1500条有标签dev |
| PEFT对照 | peft_v1：9次新训练＋3次BF16对照；20组完整test、9套辅助评价、18项原始统计 | 支撑秩/alpha/量化的候选配方与资源取舍，不支持跨所有任务的最优性 |
| 客观证据 | 28条件的表层风格、内容风险、复制与43/1453分层；最终质量/资源解释 | 给用户“效果是否可接受”的可核验检查项；代理指标不证明事实正确、深层风格或无遗忘 |
| 工程基础 | 数据/训练/完整评价/独立推理/审计脚本和统一入口；本地单卡验证 | 复用为框架后端；目前没有已验收的图形训练界面、自动硬件适配或完整任务管理服务 |

当前500条、三种子、有画像条件下，BF16 r16/alpha32 BLEU为22.0421±0.6995；r8/alpha16为22.6734±0.3356；r16/alpha16为22.6267±0.1523；NF4 r16/alpha32为22.0167±0.5416。r8可训练参数减半，allocated峰值约降2.7%；NF4整体配方allocated峰值约降38.3%、训练耗时约增14.5%。没有候选在三个种子上均取得名义BLEU区间优势，跨0不证明等效；比较未校正多重性。

因此把LoRA作为已有单卡可行性与对照证据的主实现，把BF16 r8/alpha16和NF4 r16/alpha32作为待任务验证的候选，不包装为新LoRA算法或通用最优默认值。新AI安全审查案例须独立按dev选择，不能用旧test排名直接宣布成功。详细结果以23/25/30/31号报告为准。

## 3. 仓库应提供的最短路径

1. **准备**：导入CSV/JSONL真实任务与实际回答，先按源文档分组划分，再校验角色、唯一ID、重复和授权声明，输出train/dev/test及manifest。
2. **配置**：选择已有证据支持的LoRA/QLoRA候选，清楚列出训练预算和额外dev/test；默认先校验，显式参数才启动GPU。
3. **训练**：复用模型加载与SFT组件，完整dev选择checkpoint；保存日志、输入/模型/代码哈希、完整优化器状态，支持请求暂停及核验恢复。
4. **比较/使用**：基座与适配器使用相同输入和生成预算，完整个人test核验ID/参考答案/顺序，输出指标与收据；独立推理可加载或卸载adapter回退。

开发者应能按指南运行，无需改动冻结研究脚本。通用性来自数据、任务、模型、训练、评价和适配器边界可扩展；首版明确支持范围，不宣传任意原始文件、任务和显卡都能直接微调。

## 4. 组件和接口

完整启动命令、格式字段、接口表、暂停/恢复和故障处理见[33号开发者指南](33_developer_framework_guide.md)。

| 组件 | 本轮交付 | 适用边界 |
|---|---|---|
| 规划 | planning.plan_task；personal-llm plan | 仅检查声明，不是真实文件审计/硬件自动选配 |
| 数据 | personal_data.validate_pairs/prepare/verify_prepared；prepare-personal | 真实配对，来源分组显式给出；不合成，不从原始报告编造问答 |
| 训练 | train-personal与独立personal_adapter_v1配置 | 默认只验证；--execute才加载GPU；个人dev完整评价，无旧研究1500条硬编码 |
| 运行保护 | OS GPU锁、compute PID预检、输入快照、checkpoint receipt、暂停请求 | 不提供队列/后台服务；意外断电可能损失未保存步，失败不自动重试 |
| 评价/使用 | evaluate-personal完整test包装器与已有infer | 保护覆盖及参考答案；英文风格代理不能直接解释中文专业能力 |
| 可选接入 | 文档化Python/CLI接口 | 没有声称实现REST服务、四步前端、桌面安装包或商业MVP |

新增个人路径与历史实验隔离。复用已有SFT数据/整理器、模型加载和评价代码，新增组合本轮只做CPU保护验证；真实个人GPU端到端须在后续示例中记录，不能将mock或单元测试当训练成功。

## 5. 研究证据和后续示例

50–500是训练条数，dev/test独立列入总标签预算。原有研究完整dev1500/test1496和2000次原始corpus_score配对bootstrap保持不变；新示例用实际真实材料另定完整留出集，格式上的非空下限不是足够样本量证明。

个人材料先按原始文档/会话/任务分组，再分段；精确重复与近重复都需复核，不能将LaMP问题ID当真实用户身份。未配对报告可整理和人工标注，不能自动造问题/答案。默认完整数据哈希和固定配置便于复现，来源声明的真实性仍需拥有者核实。

专业示例展示同输入、同生成预算的提示基线与适配器，检查术语/结构习惯、给定数字/实体/条件是否保持、复制风险及失败案例。指标须适配实际语种，不将BLEU/chrF或规则标记率当专业正确率、深层风格或无遗忘证明。现阶段不做人工盲评、付费强模型打分或大规模通用矩阵。

正式稳健性论证依托现有消融与多种子研究；新示例先证明开发者流程可以使用并展示边界。若未来提出自动选配、数据选择或早停的新方法，再独立冻结受控实验验证，不先宣称新算法。

## 7. 云端与本地安排

27号另行保留原平台复现协议，不能据此自动启动旧队列：固定500条、4配方×3种子=12次训练，28组完整生成、12套辅助评价、21项原始统计，独立cloud_4090_v1输出。它是已有研究的工程复现，不替代专业示例，也不随本次仓库规划追加网格。实际服务器与费用准备后再执行，本次不租机、不启动GPU。

本地small_sample_v1/peft_v1已完成，监控删除，不再运行统计或训练。只公开源码、模板、文档、哈希和聚合证据，个人材料/预测/权重/传输包留在私有目录。所有者暂不指定代码许可证，不自行添加许可或宣称正式开源发布完成。

## 8. 最终成果定位

成果由有实证依据的低资源开发框架、完整方法指南、可复现小样本与PEFT研究、一个真实专业示例及平台资源对照组成。当前没有已证明的新LoRA数学算法；贡献在实证取舍、可靠工程组合和可操作方法。最终报告分别说明完成的代码、真正运行过的流程、尚待验证的范围。


最新任务范围以34号为准：攻击案例输入＋既有风险判定/分析目标；主要评价检出与误报、macro-F1和证据支持。旧专业表达设想不是当前示例的能力目标，旧研究不因此改写。新示例优先独立云端执行，cloud_4090_v1原平台对照队列保持未启动。
