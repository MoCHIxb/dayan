# IntentTune：面向客服意图识别的小样本适配框架

2026-11-13，当前主方案。按所有者最新选择，将框架收敛到客服意图识别。IntentTune为仓库内工作名，不作商标或名称独占声明。交付是正式维护的GitHub研究仓库、命令、配置、任务目录和方法指南；不要求GUI、商业软件或立即正式开源。

## 1. 论文主线与范围

1. **可行性依据**：保留LaMP-7的50–500条研究、关键PEFT及原始统计，说明所测消费级单卡小样本适配的收益和资源取舍。它不是客服数据的实验结果，也不是每个个人各有50条训练的证明。
2. **领域框架**：提出IntentTune，将客服标签目录、真实问题接入、分组与近重复检查、低资源配方、开发集选模、完整测试和混淆诊断连成一条可复现流程。贡献是任务导向的工程与实证方法，不是新的LoRA数学算法。
3. **实践验证**：在AutoDL RTX3090上运行BANKING77固定10意图子集，比较轻量分类器、基座提示、固定示例提示和LoRA。报告收益、失败类别、格式错误和成本，不保证微调一定优于提示或轻量模型。

当前目标是用户可控制标签体系的客服任务定制，不是通用聊天安全审查、金融事实判断、自动金融交易或真实个人写作风格认证。原安全/SMS案例为历史工程验证，暂停安全数据扩充；已探查的Aegis原文件仅私有保留，未构建新训练集，未加入队列。

## 2. 领域化组件

| 组件 | 实现 | 对客服任务的作用 |
|---|---|---|
| 意图目录 | personal_llm_data.banking77.catalog/INTENTS | 固定原标签、项目定义、类别边界和closed-set范围 |
| 数据接入 | build_banking77.py、verify_banking77.py | 固定CSV版本、原文/标签回放、训练/开发/测试隔离 |
| 小样本视图 | n50/n200/n500 | 每类5/20/50条，完全嵌套，共享dev/test |
| 对照 | intent_baselines.py | 训练专用TF-IDF质心；训练集中固定10示例的基座提示 |
| 训练/恢复 | 既有train-personal | 128步、完整dev选模、完整状态与收据，不改历史运行实现 |
| 任务评价 | score-intents | macro-F1、最差类别召回、混淆矩阵和主要混淆对；严格标签JSON |
| 云端执行 | run_intenttune_3090.py及Bash入口 | 有终点、串行、证据核验后跳过、失败不自动重试 |

项目定义是任务说明元数据，不是合成客户消息、标签或训练答案。所有条件共享相同标签说明，不能把更好的任务提示只给适配器。把LLM作为意图分类器不等于它比传统模型更经济，所以保留轻量对照。

## 3. 当前数据与实施顺序

已完成CPU构建：最多500训练＋100开发＋400测试，共1000条不同源记录；50/200是500的前缀视图，不是另外750条新标注。官方完整77类仅作为固定来源，当前不称77路全量benchmark。协议见[46号](46_banking77_protocol.md)，数据卡见[48号](48_banking77_data_card.md)。

后续模型实验全部在指定RTX3090服务器上执行。本地只准备代码与数据、做CPU审计；没有运行本轮基线、训练或推理。云端指南和脚本见[47号](47_autodl3090_intenttune.md)。先核验服务器环境及资产，再显式启动有限的三训练流程，不自动恢复旧研究。

## 4. 验收与结论边界

数据必须源回放、分组隔离、完整400测试，开发集只来自官方train。每次训练恰好128步、8次完整100dev；最低dev loss且同值取最早步选择checkpoint，保留最终128步状态。每一条件完整报告，不按test决定数据大小或反复重训追分。

一种子实验先验证工程和观测效果；若要写训练稳定性，再冻结独立多种子研究，不能将旧LaMP三种子结果移植为BANKING77证据。没有OOS训练/测试，不能称未知意图检测或线上路由已验收。没有用户研究，不能称非专业用户易用性已实证。代码许可仍未指定，但所有者已明确这不是当前GitHub仓库维护或论文工作的阻塞项。
