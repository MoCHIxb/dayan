## 2. 主研究问题与数据选择

当前要验证的是：同一套IntentTune流程分别接入多个客服/服务意图领域后，每个领域的小样本适配是否比其自己的提示和轻量对照有收益。每领域训练独立适配器。它不等于用银行适配器零样本识别旅游标签，也不等于一个混合适配器同时掌握所有领域。

建议主线为BANKING77银行卡客服＋CLINC150 travel旅游服务＋CLINC150 work企业内部服务。CLINC后两者来自同一数据源，报告为三领域、两个来源，不称三个独立数据集。work不是外部商业客服，须在论文中如实称服务意图。

一手来源：[CLINC作者仓库](https://github.com/clinc/oos-eval)和[官方领域映射](https://github.com/clinc/oos-eval/blob/master/data/domains.json)。data_full每个in-scope意图有100train/20validation/30test，保留官方来源划分；travel和work均有既有领域映射。源语料是作者众包收集，不是我们的合成样本，也不冒充真实私人客户记录。

正式构建前锁定源revision、文件SHA、许可和标签目录；每领域拟固定10类以与card10的类别预算对齐。类别按业务范围及训练可用性在预测前确定，保留近义边界，不能看效果后删难类。原文和标签不改，不翻译、不扩样、不生成解释。预算或近重复审计失败则停止并在预测前修订，不自动补造。

## 3. 统一哪些内容，保留哪些差异

- 数据契约统一为原始输入、原始label、domain、source/revision/source_id、split、文本SHA；训练messages是适配视图，不改原始证据。无权重/文本公开范围扩张。
- 新领域拟建10类的嵌套50/200/500train；官方validation中固定每类10条共100dev，保留选中10类全部官方test共300条。BANKING既有100dev/400test不改、不裁成300。统一的是规则与覆盖完整性，不强求相同test条数。
- 同一Qwen3-4B固定revision、RTX3090环境、BF16 r8/alpha16、lr1e-4、累积16、128步、每16步完整dev、最小loss且同值最早。输入1536/生成64、同目录、greedy/无thinking作为拟定共同预算；正式构建时先检查所有条件含few-shot的长度，不能截断test。
- 每档四类比较：零示例、训练集每类1条固定10示例、只用该档train拟合的字符TF-IDF质心、LoRA。各方法共享标签目录与测试集，轻量模型不得用dev/test拟合特征。
- 每任务单独报告accuracy、macro-F1、最低类别召回、各类召回、invalid和混淆；同时报告相对三个对照的差值。allocated/reserved显存、训练与加载/完整评价耗时分别记录。统一工程验收不代表沿用银行0.85门槛就是所有业务的上线标准。

## 4. 有限实验与稳定性

第一步整理现有证据（本文件已完成）。第二步只做新来源/数据/长度/CPU接口审计并固定新协议。第三步在所有者RTX3090上串行运行两个新领域各50/200/500一档一种子，共6次新训练；既有BANKING三次作为历史参照，不重跑、不伪装为前瞻确认集。失败留证、不自动重试。

为论文补充稳定性，建议预先对每领域固定500条主比较增加两个训练种子：新领域各增加2次，BANKING另增加2次，共6次。首种子可作为历史探索结果，后两种子属于之后的固定验证；明确数据子集保持不变，三种子不等于三个数据抽样。总预算建议12次新训练，而非三个领域所有样本档全三种子的大网格。具体种子、执行顺序及配置须在新预测前冻结。

各领域报告种子均值/SD与最差类别变化；先逐领域展示，不把记录混池，也不按test选择获胜领域。若报告跨领域均值，只作为等权描述，标明共享CLINC来源、领域数量少和所有负结果；不当作普适有效性或统计显著性。现阶段不新增bootstrap；历史LaMP54项原统计保持不变。

## 5. 后续独立问题

联合多领域适配、留一领域泛化、OOS拒识、中文、其他基座、用户易用性均是不同问题，不能由本轮结论代替。当前优先完成多领域同任务对照与稳定性；不同时加入这些变量。

工程需将目前BANKING专用catalog/输入抽取/基线入口参数化为通用意图任务适配层；核心训练、分类评分和历史收据保持不变。旧intent_baselines.py依赖banking77 LABELS及user_request封装，不能仅替换数据路径就声称支持新数据。新任务目录与执行器另建输出，并对标签、split、训练专用拟合和完整预测覆盖作CPU验证。

所有新训练仍由所有者在云端命令行显式启动；本次没有创建自动运行队列、租用服务器或触发GPU。
